## 1. The 65 % rule, and how it is enforced

GG's formula is **User price = Cost ÷ (1 − 0.65)**. The engine applies it to what we actually keep, not to the sticker price:

- **Cost ₾** = Google USD × 2.7 ₾/$ × 1.05 (FX reserve against a weaker lari). Retries and hosting are already part of the USD cost.
- **Net ₾ per credit** = 0.08 ₾ floor × (1 − 3 % BOG card fee) ÷ (1 + VAT). That is 0.0776 ₾ today (VAT 0).
- **Credits** = ⌈Cost ₾ ÷ (0.35 × net ₾ per credit)⌉. That works out to 104.38 credits per $1 of Google cost.

Margin is computed at the **floor** credit (0.08 ₾), the cheapest credit any package may sell. So the rule holds whichever package paid for the credit. A top-up buyer at the 0.10 ₾ sticker gives about 72 %.

Enforcement points (`lib/billing/margin/`):

| Where | What stops a price under 65 % |
|---|---|
| `econ.enforceMargin(credits, costUsd)` | The single gate. Any asked price under the minimum is raised to it (0, NaN and fractions too) |
| `catalog.priceList()` | Prices are computed from COGS, never typed in. `margin.test` fails the build if any row is under 65 % at the floor |
| `packages.packageProblems()` | Refuses a plan or top-up that sells a credit under 0.08 ₾, or that goes over BOG's 500 ₾ single payment |
| `margin.test` worst case | Every plan spent entirely on its lowest-margin action still keeps ≥ 65 % after card fee and VAT |
| VAT / weaker lari | Change `vatRate` or `gelPerUsd` and every price rises by itself (tested at 18 % VAT and 3.1 ₾/$) |

Wiring into the live charge path happens in a later PR, behind a flag, after GG approves the numbers. The engine is built so `lib/credits/priceBook.ts` can read from it and `#313`'s `priceVersions.rowProblem` can call `minCreditsPerUnit`.

## 3. Founder Admin Dashboard (draft PR 2)

A new **Finance** tab in `/[locale]/admin`, admin-only, behind `ADMIN_FINANCE_DASHBOARD` (off by default).

`GET /api/admin/finance?days=30` (service role, admin gate, read-only):

| Figure | Source |
|---|---|
| Total revenue (₾) | `wallet_topups` (BOG top-ups) + `bog_orders` `status = 'completed'`, kind subscription/renewal (same split as `/api/admin/financials`) |
| Google Cloud cost | `provider_costs` (from #313) per call = **estimated**; replaced by `reconcile_reports` per day = **reconciled** |
| Net profit, margin % | revenue after card fee and VAT − Google cost (`finance.summarize`) |
| Paid usage margin | credits charged × net ₾ per credit vs their cost (shows if free credits drag the realised margin down) |
| User usage table | top credit burners: `credit_ledger` spend (delta < 0) + `provider_costs`, with plan, cost and margin per user |
| Margin alerts | `alerts.marginAlerts`: MARGIN_LOW (< 65 %, critical < 50 %), COST_SPIKE (cost per call +15 % vs the previous window), UNPRICED (cost with 0 credits, > $1) |

If a table is missing (e.g. `provider_costs` before #313's migration runs), the route returns the other figures and marks that part "not available yet". It never errors the page.

## 5. Risks for GG

1. **Free live avatar.** The free plan's perk "1 avatar session a day (5 min)" costs about $2.08 per active free user per day (44 credits a minute). 50 sign-up credits cover about 1 minute. Recommend dropping it to 1 minute a day, or making it paid-only.
2. **VAT.** If MyAvatar registers for VAT (18 %), every price rises about 22 %. The engine does this by itself when `vatRate` changes.
3. **Google promo pricing.** Gemini 3.8 Flash and Flash TTS are at half price until 2026-12-31. The matrix uses full prices on purpose, so the promo is extra margin, not a cliff on 1 January.
4. **Price rise for current users.** Every action gets about 1.7× dearer. Suggest honoring today's prices for existing balances for 30 days, then switching.
5. **Free and admin credits** are spent with no revenue, so the realised margin can sit under 65 % even when every price is right. The dashboard shows both numbers.
6. **Live minute.** The live avatar keeps a 40K-token context per minute in the estimate. A real call trace after the DB is back will confirm or move the ✦44.
