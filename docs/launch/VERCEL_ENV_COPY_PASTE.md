## How to use it

1. Vercel → project → **Settings → Environment Variables** → **Add New**.
2. **Key** = the `Variable` column, character for character. **Value** = the `Paste` column, without the backticks.
3. **Environment: Production** only, unless the row says otherwise. Previews share Production's database and wallet,
   and paid generation is blocked on them anyway (`lib/env/previewIsolation`).
4. **Redeploy** (Deployments → latest Production → Redeploy). Vercel applies a change only to deployments made after
   it, and a `NEXT_PUBLIC_` name is baked into the browser bundle at build time.
5. Open `/api/admin/launch-flags` signed in as an admin (after #396 is merged). Every switch should read the way you
   meant it, and the logs should show no `[launch-flags]` warning.

**To turn a switch OFF:** delete the variable (or set it to an empty value) and redeploy. Unset means off for every row
below. Do not type `0`, `false` or `off` and expect the same thing everywhere; unset is the only value that is off in
every vocabulary.

**The vocabularies differ** (#396 documents this, it does not unify it). `admin` turns on the studios but is **OFF**
for `AGENT_REEL_TASK`, which needs `admins`. `true` turns on `PRICING_V8` but is **OFF** for `BROWSER_ENABLED`, which
needs exactly `1`. The `Paste` column already has the right word for each row; the first value given is the
admins-only one, so a feature is tried on GG's account before anyone else's.

**Secrets** (`secret` in the table) are never written here and never generated by Claude. GG creates or copies the
value and adds it as a **Sensitive** variable.
