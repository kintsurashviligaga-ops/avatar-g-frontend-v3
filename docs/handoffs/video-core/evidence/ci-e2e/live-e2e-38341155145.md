## The six failures — root cause (DEFECT_REGISTER_FINAL.md row 38)

The source was the montage master's signed URL, `http://supabase.video-core-e2e.test:54321/storage/v1/object/sign/renders/…`.
`lib/security/callerMedia` `resolveCallerMedia` takes a URL of ours only over https (Production serves https) and
`lib/orchestrator/storage-adapter` `parseSupabaseObjectUrl` recognised storage objects only on `*.supabase.co`: so the
URL was `invalid` here (`unreadable`), and over https it would have parsed as an external file (`media_not_yours`).
Production's storage host is a `*.supabase.co` name, so Production never met this; a deployment whose Supabase is
served under another name (a custom domain, a self-hosted or local stack) would have.

Fix 38a6167: the parser also accepts this deployment's own Supabase host (`ownStorageHosts`); with Production's env the
accepted hosts are exactly the same, pinned by a test. The CI stack is now served over https by a TLS front
(`e2e/video-core-live/scripts/tls-front.mjs`) with a certificate from a CA the job makes for that run only
(`make-tls.sh`: the CA key is deleted as soon as the leaf is signed; nothing is printed or uploaded); Node trusts it
through `NODE_EXTRA_CA_CERTS`, the browser only in the isolated Playwright config. The SSRF rule of
`lib/web/publicFetch` is untouched. Result of the rerun: `live-e2e-38348318160.md` (run 6: the edit lane reached and 2× / slow motion delivered on both viewports; the trim was defect 39).
