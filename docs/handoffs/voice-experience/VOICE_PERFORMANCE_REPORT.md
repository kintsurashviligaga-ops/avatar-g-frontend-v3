# Performance and reliability
No real provider or microphone measurement: n=0. First audible response p50/p95, capture-to-provider delay, barge-in cutoff, reconnect recovery time and Georgian listening score are **NOT MEASURED**. Jest or browser test duration must not be presented as audio latency.
Existing bounds: microphone acquisition classification/retries, mint deadline and playback teardown remain in the native hook. New TTS/reader synthesis aborts after 30 seconds; stale completions are epoch-fenced. Reader serializes requests instead of generating an entire long document at once.
Local validation: targeted Jest 49 suites / 1,029 tests in 5.39 seconds; additional session regression suite 58/58 in 1.35 seconds. These are test execution durations only.
Performance acceptance run: after approved isolated Google credentials/budget, collect at least 30 turns per browser/device/network scenario, monotonic timestamps for user speech end / first PCM / first audible output / interruption detection / final stopped source. Report median, p95, failures and sample size separately. Use existing liveTelemetry fields; do not log tokens, raw audio or transcript by default.
Timeouts: TypeScript/Jest/lint 180 seconds per local invocation; browser whole run 720 seconds, individual 120 seconds, server 180 seconds; build 600 seconds. No --forceExit. CI job limits are committed in voice-experience.yml.
