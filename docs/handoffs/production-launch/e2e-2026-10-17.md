## The redo defect (PR #95)

Root cause: `restitchBody` (`lib/chat/filmSceneRedo.ts`) dropped the film's brief (`scorePrompt`) whenever it reused the music, to avoid composing a new score. The assembler reads that brief for the LUT look as well (a night brief picks `night_neon`; without it the default `cinematic`), and for music-video mode, the commercial overlay and the Library row's prompt. The music is already pinned by `musicUrl`, which the assembler uses before it would compose, so the brief now always travels with the redo. Regression test in `filmSceneRedo.test.ts` fails on the old code and passes on the new. Proving it live needs PR #95 deployed and one more scene redo (about $0.8).
