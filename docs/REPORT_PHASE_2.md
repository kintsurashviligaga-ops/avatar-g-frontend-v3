## 3. რეალური E2E — და ნაპოვნი production ბაგი

`scripts/studio-e2e.ts`: ერთი რეალური გენერაცია production-ის Supabase-სა და Higgsfield-ზე, GG-ის ანგარიშით.

| ნაბიჯი | შედეგი |
|---|---|
| ფასი | Soul 2 → $0.004 → **1 კრედიტი (0.10 ₾)** |
| ჩამოჭრა | ბალანსი 879 → **878**. ledger-ში ზუსტად ერთი ჩანაწერია: −1, `studio:<job>` |
| თარგმანი | „მზის ჩასვლა თბილისის ძველ უბანზე…“ → „Sunset over the old district of Tbilisi…“ |
| webhook | production-მა `completed` 55 წამში მიიღო. HMAC ემთხვევა, ჩანაწერი შენახულია |
| **შედეგის კოპირება** | ❌ **„Bucket not found“** |

**ბაგი:**
- `studio` bucket არასდროს შექმნილა. კოდი bucket-ის შექმნას `try/catch`-ში ცდილობდა, მაგრამ supabase-js შეცდომას არ აგდებს — აბრუნებს. ამიტომ წარუმატებლობა უხმოდ იკარგებოდა.
- შექმნა კი მართლა ვერ ხერხდებოდა: 256MB ლიმიტი აჭარბებს პროექტის გლობალურ ლიმიტს.
- შედეგი: **ყოველი დასრულებული სტუდიის შედეგი ჩარჩებოდა `finalizing`-ში**, თანხა კი ჩამოჭრილი იყო.

**გამოსწორება:**
- production-ში `studio` შეიქმნა ხელით (private). ეს დამატებაა, არსებული არაფერი შეცვლილა;
- კოდი (`ensureBucket`) ახლა პასუხს კითხულობს და ზედმეტ ლიმიტს ლიმიტის გარეშე იმეორებს;
- ჩარჩენილი job მომდევნო cron-ზე დასრულდა: output შენახულია, Library-ში ჩანაწერია, signed URL → 200 image/png 2.5 MB.
